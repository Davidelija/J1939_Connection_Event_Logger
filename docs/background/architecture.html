SYSE 549 · J1939 connected-devices event logger

Event logger system architecture

How the logger taps the diagnostic port, turns CAN frames into connection events, and identifies new devices against a trained list of known-good connections.

Prototype platform

The DG Beacon is the prototype platform because the team already has two, they are rated for vehicle use (6–32 VDC, −40 to +85 °C), and they run Linux with multiple CAN channels. It is a development and test instrument, not an installation device: its size, its roughly 1.6 A draw, and mounting it at the diagnostic port make it unsuitable for permanent installation in a fleet vehicle. The logger software is written for Linux and SocketCAN so it can move to a smaller, low-power in-vehicle logger for deployment.

Scope

In scope

  • J1939 on CAN
  • Address claim and NAME, including a periodic address-claim sweep
  • New source address, including devices that never claim an address
  • Address-claim conflicts
  • All PGNs sent by an unrecognized source address; requests kept in order
  • Control PGN flags: TSC1, TC1, XBR, Commanded Address, Reset, DM11 clear codes
  • Responses to an unknown source address
  • Diagnostic messages: DM1/DM2 requests, DM3/DM11 clears, DM14–DM16 memory access, DM18 security
  • Self-reported identity: Component, Software and ECU ID
  • Proprietary PGNs, logged but not interpreted
  • New PGN from a known or approved device (pending a check with ORNL)
  • Vehicle ECUs not in the baseline and trailer devices, classified separately

Out of scope

  • Timing and cadence detection
  • Below-message detection
  • Identifying devices that do not claim an address, beyond the PGNs they send
  • Devices sharing a source address without claiming it
  • Other atypical behavior from a known source address, such as timing
  • Networks other than the single J1939 network at the 9-pin port; 16-pin connectors (known limit)
  • Interpreting proprietary PGN content
  • Listen-only devices
  • J1708/J1587 (needs different hardware)
  • Physical tamper protection (seals, locked enclosure)

Future work

  • ISO 15765 diagnostics over CAN (same hardware, decoding only)
  • Fleet profiles: shared inventories for trucks of the same configuration
  • Onboard screen in place of the maintenance laptop
  • Two-person approval for control PGNs and removing trained ECUs
  • Deferred from the prototype: signed seals, operator and admin roles, signed updates and rollback, move and wipe, library push, internal-flash fallback, 7-day soak, fuzz testing, Linux laptop support
